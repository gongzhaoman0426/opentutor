配套文档：[技术方案](./technical-design.md)

## 1. 产品定义

OpenTutor 是一个开源的全栈 Web 应用，把用户提供的 Markdown 文稿和图片，转成带旁白、字幕、图文与可视化的视频，并支持在网页中预览、修改和导出。适用内容包括产品介绍、业务汇报、观点分享、故事叙述、操作演示、知识讲解，以及其他适合这种表达形式的视频。

核心价值是理解作者想表达什么，为素材安排合适的结构、画面、节奏与旁白。系统根据内容和创作要求选择表达方式；产品发布可以突出特性，汇报可以突出变化与结论，故事可以保留事件顺序和情绪，教学内容可以逐步解释。默认不强加学习目标、课堂开场、知识测验或教学总结。

长期愿景是让任何人都能像写 Markdown 一样创作视频，逐步形成视频 DSL、组件和插件生态。品牌保留 OpenTutor；教学是支持的用途之一。首版以可用的图文视频制作闭环验证这条路径。

## 2. 已确认方向与本稿假设

### 2.1 已确认的产品方向

| 编号 | 已确认方向 |
| --- | --- |
| C-01 | 产品是完整的前后端 Web 应用，网页是用户操作入口。 |
| C-02 | 支持任意适合图文、图解、旁白与字幕表达的 Markdown 内容端到端生成视频，不按学科或用途设置白名单。 |
| C-03 | 用户无需把文稿改写成特定模板；系统负责理解原有结构、表达目的和素材关系，形成合适的视频编排。 |
| C-04 | 首版不包含 VTuber、数字人、角色动作和口型。 |
| C-05 | 使用 Codex harness 作为后台 AI 引擎，驱动内容规划、讲稿、DSL 生成及诊断修复。 |
| C-06 | 主页创建项目；独立编辑页按章节编写 Markdown，右侧切换 Markdown 预览和视频预览。 |
| C-07 | AI 生成结构化视频表示，由程序完成可检查、可复现的渲染。 |
| C-08 | 首版 TTS 使用微软免费语音服务，不要求用户购买配音服务或提供付费 TTS API key。 |
| C-09 | 制作页保持单屏，章节目录、Markdown 编辑器和预览各自内部滚动；项目设置不占据主流程。 |
| C-10 | “生成视频”自动完成理解、编排、配音和交互预览；仅在“下载视频”时渲染 MP4。已有或部分完成的视频随时可预览。 |
| C-11 | AI 接收 Markdown 引用图片的真实像素，结合章节上下文决定展示、讲解、裁剪和高亮。 |
| C-12 | 一个章节生成一个独立视频，预览、生成参数和下载均按章节保存。 |
| C-13 | 生成前可调整分辨率、微软音色、风格描述或预设模板、Codex 模型与创作／稳定模式。 |
| C-14 | 创作模式允许 AI 大量使用自定义代码组件；稳定模式仅使用预设组件；作者可以预览所有现有组件。 |
| C-15 | 默认自动判断视频用途；可选择用途预设并填写自由创作要求，预设不限制可创作类型。用途、受众和创作要求按章节保存，并传入概览、分镜和局部重生成。 |

### 2.2 本稿采用的设计提议

- 默认采用完整内容模式，保留主要内容要点、原有示例和关键限定条件；摘要模式需要用户主动选择。
- 长文稿按章节处理，视频时长随内容增长；预估时长用于提示，不构成静默删减内容的理由。
- 首版以单作者的项目制作流程为中心，用户体系、多人协作和托管运营规则另行决定。
- 提供四种视觉模板、微软音色选择和 720p/1080p 横屏 MP4；可用一句话描述风格。
- 微软免费 TTS 按 Microsoft Edge 在线朗读服务落地，通过 `edge-tts` 在后台接入；具体音色经试听确定。该接入无需 API key，但仍需联网。[接入项目说明](https://github.com/rany2/edge-tts)
- 文档中的数量、时延、质量阈值均为建议验收目标，不是已确认的用户要求或实测结果。

## 3. 目标用户与主要使用场景

| 用户 | 当前需求 | OpenTutor 提供的价值 |
| --- | --- | --- |
| 产品与团队作者 | 从产品说明、更新日志或方案制作介绍视频 | 使用真实截图、功能关系和准确文案，保留事实边界。 |
| 信息与观点作者 | 从报告、文章或数据制作摘要、复盘和观点视频 | 组织论点、数据与结论，保留来源和限定条件。 |
| 叙事与内容创作者 | 从故事、游记或图文记录制作视频 | 保留叙事视角、事件顺序和情绪，用图像与节奏组织内容。 |
| 教师、培训讲师及知识分享者 | 从讲义、笔记或代码示例制作讲解视频 | 按需解释概念、演示过程，保留审阅和修改入口。 |

首版关注作者将已有内容转成可编辑的视频。用途预设是编排偏好，不是独立产品流程；所有用途共用编辑、素材、预览和导出链路。

## 4. 首版范围

### 4.1 包含

- Markdown 文件上传、文本粘贴和配套图片素材管理。
- 默认配置即可生成；配音等设置作为可选入口，不要求创建时填写。
- 一键理解文稿与图片、规划表达结构、生成旁白、场景、配音、字幕和同步预览；下载时渲染。
- 通用视频画面，以及基于可靠能力的公式、代码、流程和步骤展示。
- 可恢复的生成任务、可理解的进度、取消、失败重试和诊断展示。
- 场景列表、视频预览、基础场景编辑、版本记录和局部重建。
- MP4 导出和最终结果下载。

### 4.2 “任意 Markdown”的实际含义

输入覆盖不同主题、用途及常见 Markdown 结构，包括标题、段落、列表、引用、链接、表格、图片和代码块；公式与 Mermaid 等扩展需明确支持语法并给出诊断。

不同用途共享基础呈现能力。当前呈现形式以图文、图解、图表、代码、公式、动态 SVG 和旁白为主；扩大用途不会自动增加真人拍摄、写实视频生成或任意素材剪辑能力。专门演示能力可以逐步增加；遇到能力边界时应使用可靠的基础表达，保留原文事实、叙事关系和作者意图。

缺失图片、无法解析的语法、相互矛盾的文稿或不可验证的演示不能静默跳过。必须展示问题、关联来源，并区分“可继续生成的提示”和“阻止完成的错误”。

不要求统一文稿格式，但需要提供可读内容和实际引用的必要素材。输入限制及长文边界应在提交前可见，具体限制由容量测试决定。

## 5. 用户主流程

1. 主页输入项目名称创建项目，进入独立编辑页。
2. 左侧添加、重命名和排列章节；中间按章编写 Markdown，也可以导入 `.md`。
3. 上传、拖入或粘贴图片，将稳定的素材引用插入编辑器。右侧即时预览文稿。
4. 点击“生成视频”，默认自动判断用途；可选填用途、受众与创作要求，再选择分辨率、音色、画面风格、模型和生成模式。确认后冻结本章输入，后台参考全项目关系，只编排、配音和生成当前章视频。
5. 右侧切换“视频”查看生成结果；生成中保留上一版，并逐步提供当前版本已完成的场景与配音。未配音部分明确标记。
6. 继续修改文稿，重新生成需要更新的视频。后台旧任务不能覆盖后续输入。
7. 点击“下载视频”，对完整且属于当前版本的预览执行 MP4 渲染；完成后下载。同版本已有成片时直接复用。

生成不要求作者理解 DSL、单独点击配音或预先渲染。底层各阶段仍独立可检查、取消和恢复。运行状态和问题按需展开，避免把基础设施概念放进作者主流程。

## 6. 页面与信息结构

| 页面或区域 | 核心内容与操作 |
| --- | --- |
| 主页 | 项目列表、搜索、输入名称创建、打开与删除项目。 |
| 编辑页顶部 | 返回主页、项目名、保存状态、“生成视频”和“下载视频”。 |
| 左侧章节目录 | 新增、选择、重命名、排序、删除章节；目录可以收起。 |
| 中间编辑器 | 当前章节 Markdown、文件导入、图片插入；正文内部滚动。 |
| 右侧预览 | “Markdown / 视频”切换；文稿排版与真实图片，或带声音、字幕和定位控制的视频。 |
| 辅助区域 | 图片素材、任务详情、诊断、历史和可选设置按需打开。 |

整体制作页不采用长页面布局。窄屏允许切换编辑与预览，不能把所有区域压成难以使用的窄列。详细交互见[工作台设计](./workbench-design.md)。

## 7. 功能需求

### 7.1 输入与项目设置

| 编号 | 要求 | 首版验收行为 |
| --- | --- | --- |
| FR-001 | 支持上传 `.md` 文件或粘贴 Markdown，保存原始内容。 | 两种输入进入相同生成流程；刷新后内容仍可访问。 |
| FR-002 | 解析并展示章节、内容块和素材引用，保留来源映射。 | 场景能定位到对应原文章节或内容块。 |
| FR-003 | 支持补充图片并解决 Markdown 图片引用。 | 缺失素材有明确提示；映射后的图片可预览并进入视频。 |
| FR-004 | 提供可选视频用途、创作要求、目标受众、旁白语言、完整／摘要模式、配音与画面风格配置。 | 默认自动判断用途，受众为普通观众；生成和导出采用所属版本的配置。创作要求与配色描述独立。 |
| FR-005 | 处理空文档、损坏文件、超限输入和不支持的语法。 | 提交前尽量诊断；不能处理时给出具体原因及处理建议。 |
| FR-006 | 外链和嵌入内容具有明确处理规则。 | 网页链接默认作为引用；不可执行原始 HTML，未支持的嵌入明确标记。 |

### 7.1.1 图片与章节

- 每章具有稳定 ID、标题和 Markdown；章节排序、改名、内容与素材修改进入版本控制。
- 每章独立保存参数、预览和成片；其他章节的编辑和生成不使当前章视频失效。当前章内容或设置变化保留旧视频供查看，更新后才能下载当前版本。
- 图片使用 `asset://<素材ID>` 引用，改文件名不影响引用；旧同名路径仅在唯一匹配时兼容。
- 行内与引用式 Markdown 图片均可解析；同一素材在不同位置出现时分别记录用途。
- 缺图、同名歧义、损坏图片和未支持远程图片需明确报告，不猜测或读取任意服务器路径。
- AI 先读取图片内容，再结合所在章节、图片前后的说明和全项目关系编排。文件名和 alt 仅为上下文，不能替代视觉输入。
- 图表、示意图、照片与界面截图可采用不同讲解方式。裁剪和高亮必须有可定位依据；不确定区域时展示完整原图，并保留不确定提示。
- 每个已引用图片必须进入关联来源的画面，并在相应讲稿期间显示。结构校验不能代替人工判断讲解是否准确。
- 空章允许保存；当前章节没有可呈现正文时不能生成，不影响其他章节生成。

### 7.2 内容规划与内容生成

| 编号 | 要求 | 首版验收行为 |
| --- | --- | --- |
| FR-010 | 自动提取主题、内容要点、示例、术语和必要的前后关系。 | 编辑器能够查看章节与主要内容要点的覆盖情况。 |
| FR-011 | 将文稿组织成符合用途的场景和旁白。 | 产品、汇报、故事与讲解可采用不同节奏和结构；不为非教学内容强加课堂模板，避免整页密集文字。 |
| FR-012 | 完整内容模式保留原文关键内容和限定条件。 | 被合并、改写或无法处理的内容仍有映射；遗漏可识别。 |
| FR-013 | 摘要模式明确表现取舍。 | 用户先选择摘要；输出展示保留内容和主要省略范围。 |
| FR-014 | 长文分章处理，保持术语、符号、主题和场景衔接。 | 章节不会重复生成整份前言或丢失跨章节引用。 |
| FR-015 | 可补充必要衔接和表达组织，但不改变原文事实或作者意图。 | 产品参数、数据、引语和事件不凭空添加；故事保留来源设定和虚构属性。用途和创作要求不能充当缺失事实的依据。 |
| FR-016 | Codex 驱动 DSL 生成和基于诊断的有限自动修复。 | 失败超过修复预算后报告原因、受影响场景及可执行下一步。 |

### 7.3 画面、声音与同步

| 编号 | 要求 | 首版验收行为 |
| --- | --- | --- |
| FR-020 | 支持标题、正文、列表、表格、图片、代码、公式和关系图。 | 同一项目可混合这些内容；字幕和画面无明显裁切或遮挡。 |
| FR-021 | 支持分步显示、高亮、替换、移动及节点和箭头的基础组合。 | 示例过程随讲稿逐步展示，动作目标存在且可追踪。 |
| FR-022 | 对无法完成的复杂演示提供可信回退。 | 可使用原图、分步公式、代码快照或内容卡片；不得编造结果。 |
| FR-023 | 生成配音、字幕和与语音关联的画面时间。 | 修改讲稿或语速后重新对齐；字幕与可视化锚点不沿用失效时间。 |
| FR-024 | 检查可验证的示例和结果；展示检查范围。 | 检查失败不能当作通过；未验证的知识或演示明确标记。 |
| FR-025 | 保持项目内的视觉和听觉一致性。 | 字体、配色、术语呈现和音量统一；无缺失音频或空白坏帧。 |
| FR-026 | 使用微软免费 TTS，提供可用音色、语速设置和试听。 | 无需填写 TTS API key 即可生成配音；复用有效音频；服务不可用时展示原因并支持重试，不自动切换到付费服务。 |
| FR-027 | 静态与动态均可表达内容；动作需服务信息、叙事、情绪或构图。 | 不为证明“创作模式”而重复添加匿名移动小球。讲解过程可停留在结果，叙事转场可服务节奏，真正的周期过程可循环。 |

### 7.4 编辑与重建

| 编号 | 要求 | 首版验收行为 |
| --- | --- | --- |
| FR-030 | 编辑器支持按章节浏览、选择、预览和调整场景顺序。 | 重排后顺序保存，并更新衔接诊断和导出顺序。 |
| FR-031 | 支持修改当前场景的讲稿、标题、内容、图片和少量视觉参数。 | 修改可保存；先校验再预览；非法参数不能进入渲染。 |
| FR-032 | 支持重新生成选定场景并提供修改意图。 | 生成范围清晰；用户手动内容默认保留，替换前展示受影响项。 |
| FR-033 | 根据修改内容局部重建，显示失效范围和状态。 | 单一视觉修改复用有效音频；讲稿修改重新生成所需音频与时间轴。 |
| FR-034 | 支持修改源文稿后生成新版本。 | 不覆盖旧版本；提示需重新规划的章节及可能失效的场景修改。 |
| FR-035 | 保存项目与生成结果的版本关系。 | 预览、诊断和导出显示版本，不能把旧视频展示成最新编辑结果。 |

### 7.5 任务与导出

| 编号 | 要求 | 首版验收行为 |
| --- | --- | --- |
| FR-040 | 后台运行耗时任务，支持刷新后继续查看。 | 页面关闭或刷新不会被当作主动取消。 |
| FR-041 | 展示真实阶段和可计算的阶段进度。 | 无总量时用阶段和完成项表达，不使用虚构百分比或 ETA。 |
| FR-042 | 支持取消和失败重试。 | 取消有确认结果；重试复用仍有效的产物并保留失败诊断。 |
| FR-043 | 防止重复点击产生重复任务或混淆结果。 | 明确当前运行版本；重复请求返回已有任务或清晰说明。 |
| FR-044 | 导出 MP4 并提供下载。 | 文件可播放、有声音和字幕，版本与用户选择一致。 |
| FR-045 | 编辑与导出允许并行但需要版本隔离。 | 导出固定提交时的版本；后续修改不偷偷进入正在运行的导出。 |

## 8. 编辑与版本一致性规则

项目源稿、生成的场景与讲稿、预览产物和导出视频是不同层次的内容，每次生成或导出必须绑定一个不可变版本快照。

- 生成与场景重生成形成新的结果版本，不把结果补写到输入版本；纯导出固定已有项目版本。
- 保存修改后，立即显示“已保存，预览待更新”，同时列出需重建场景。
- 旧预览可以继续播放，但必须显示所属版本和过期状态。
- 重建完成后，用户看到对应版本的预览；失败时保留已存在的有效版本。
- 自动修复不得静默覆盖作者后续编辑。后台结果与当前编辑不一致时，保存为独立候选版本。
- 取消先被接受时，晚到的生成结果不得发布为当前预览；完成先提交时，取消操作说明任务已经完成。
- 调整顺序或删改章节应重新检查衔接、覆盖、总时长和全局时间轴，局部重建不意味着忽略全局依赖。
- 局部重建复用未受影响的内容、音频和场景工件；最终 MP4 仍可能需要重新编码整片，界面应如实表达。
- 删除项目是明确操作，并提示项目素材和结果的处理范围；具体保留策略待确认。

## 9. 任务状态与异常行为

| 状态 | 用户可见含义 | 后续操作 |
| --- | --- | --- |
| 待处理 | 已接收请求，尚未执行。 | 查看排队状态、取消。 |
| 运行中 | 正在规划、生成、校验、配音、同步或渲染。 | 查看阶段和诊断、取消。 |
| 取消中 | 已请求停止，正在结束执行并清理。 | 等待终态，不把请求已发送当成已取消。 |
| 已取消 | 执行已停止，已完成产物可以按版本保留。 | 从有效阶段继续或重新生成。 |
| 成功 | 所需产物存在，执行与技术检查完成，没有未解决的阻塞问题。 | 预览、编辑、导出或下载，同时查看内容质量诊断。 |
| 失败 | 当前任务无法完成。 | 查看具体原因、补充素材、修改或重试。 |

任务执行状态与内容质量状态独立：`passed_checks` 表示已执行的检查通过，`needs_review` 表示存在需复核内容，`blocked` 表示存在阻止后续处理的问题。运行成功可以同时有需复核提醒，不自动等于失败，也不默认强制每个视频人工审批。

“生成成功”不等于内容审阅通过。界面展示已执行的技术检查与需作者复核的内容；事实准确性、叙事忠实度与风格适配不能由结构校验代替。明确的技术阻塞不能被标为成功。

错误应至少提供阶段、原因、受影响章节或场景、可重试性及下一步。原文矛盾、素材缺失等问题需要作者处理；提供方超时、临时渲染失败等问题可以有限重试。

## 10. 非功能需求

- 可靠性：任务和产物持久保存，进程中断后可恢复；部分失败不破坏已有版本。
- 性能：长任务异步运行；展示阶段进度。最大文稿规模、并发和生成时延依据测试设定并公开限制。
- 可维护性：项目结构和 DSL 有版本，诊断可追踪；保留阶段、重试和成本信息用于定位问题。
- 可读性：正常播放尺寸下正文、代码、公式和字幕可辨认；不能依靠暂停放大弥补默认布局。
- 可访问性：核心操作有明确标签和键盘路径，状态变化可读；字幕可关闭或按导出设置处理。
- 数据边界：页面说明文稿和素材会发送给哪些已配置服务；密钥不进入浏览器、项目内容或导出文件。
- 开源交付：提供源码、安装运行说明及依赖许可说明；具体许可证和自托管方案待确认。

## 11. 建议验收目标与测试方法

以下指标用于制定首轮验证计划，应先测量基线再确认阈值；不能作为已实现能力对外宣传。

| 维度 | 建议验收目标 | 检查方式 |
| --- | --- | --- |
| 端到端闭环 | 不经逐阶段人工干预完成导入、生成、预览、修改、重建、导出。 | 浏览器完整操作；刷新与恢复检查。 |
| 通用性 | 至少覆盖产品介绍、信息汇报、观点分享、故事叙述和知识讲解五类文稿。 | 每类至少两份未经模板适配的真实文稿，共不少于十份；额外检查自动用途和自由创作要求。 |
| 首轮完成率 | 测试集中至少 80% 产出可预览的视频，且无未解决的阻塞诊断。 | 记录全部失败、回退和重试，不剔除失败样本。 |
| 内容完整性 | 完整模式的主要内容要点、示例和关键限定条件均有来源映射。 | 原作者或领域审阅者逐项核对；记录新增内容和遗漏。 |
| 内容忠实度 | 没有虚构产品参数、报告数据、引语和事件；叙事保持来源设定，知识讲解没有重大事实错误。 | 作者或领域审阅者与程序检查分别记录，不能相互替代。 |
| 画面和同步 | 无明显文字裁切、目标失效、缺失素材、无声片段或关键讲解错位。 | 自动诊断加正常速度观看；精确偏差阈值另经测试确认。 |
| 编辑有效性 | 视觉、讲稿、顺序和源稿四类修改都正确触发失效与重建。 | 比较重建范围、预览版本和最终视频。 |
| 作者价值 | 建议至少三位作者愿意制作下一个视频，总人工时间较原流程降低 50%。 | 记录审阅修改时间、成片接受度和真实制作对照。 |

边界样本还应包含：无标题文稿、长章节、混合语言、代码与公式混排、宽表格、缺失图片、错误 Mermaid、超长代码、相互矛盾内容和不支持的嵌入。另测网络失败、任务中断、取消后重试及编辑期间旧任务返回。

## 12. 明确排除的首版内容

- VTuber、Live2D、数字人、角色素材、口型和动作系统。
- PDF、PPT、网页和第三方知识库直接导入；仍可作为后续输入扩展。
- CLI 作为产品入口、Electron 桌面客户端和移动原生客户端。
- 完整多轨时间轴、任意动画关键帧编辑和专业剪辑软件级功能。
- 公开 Hub、插件商城、社区角色、项目发布平台和付费市场。
- 多人实时协作、学习管理系统、学生测验运营和个性化学习推荐。
- 首版必须覆盖任意专用仿真、任意动态代码或任意学科的自动事实核验。

上述排除不阻止通用端到端生成：复杂内容通过可靠的基础表达与明确诊断处理，后续再扩展专用能力。

## 13. 待确认事项

1. 部署形态：自托管优先、托管服务优先，或两者共用同一套架构；据此确定登录、权限和配额。
2. 首版支持的讲解语言、微软免费 TTS 的具体音色与声音数量，以及默认语速。
3. 默认主题、视频比例、分辨率、字幕导出形式和可调视觉参数。
4. 单份文稿规模、并发任务、生成成本或时长预算，以及超限后的明确处理规则。
5. 不可验证内容的确认入口，以及何种诊断必须阻止最终导出。
6. 项目历史、素材和视频的保留策略；是否需要下载可编辑项目包。
7. 核心代码许可证、外部依赖许可与后续生态协议。

这些事项不改变已确认的 Web 应用、任意 Markdown、无 VTuber、Codex harness 和微软免费 TTS 方向；实施时应记录决定，再更新本稿。
