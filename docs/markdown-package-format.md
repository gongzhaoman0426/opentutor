# Markdown 章节压缩包规范

更新时间：2026-10-11

将一份 Markdown 与它引用的图片放进同一个文件夹，压缩为 ZIP，即可一次导入某个指定章节。导入不会按标题拆章；一份压缩包对应一章文稿。

## 文件夹结构

ZIP 内必须只有一个顶层文件夹，该文件夹的整个目录树中必须有且只有一个 `.md` 或 `.markdown` 文件，扩展名不区分大小写。Markdown 使用 UTF-8 编码，建议放在顶层文件夹中，也可以放在子目录。

图片可以放在这个文件夹内的任意位置，使用 PNG、JPEG 或 WebP 静态图片。Markdown 中的图片路径必须相对于 **Markdown 文件所在目录**，并且能找到包内的对应文件。

```text
产品更新/                    ← 压缩这个完整文件夹
├── 正文.md                  ← 整个目录树中唯一的 Markdown
├── 封面.png
├── images/
│   ├── 桌面 预览.webp
│   └── 流程.jpg
└── 对比/
    ├── 旧版/
    │   └── result.png
    └── 新版/
        └── result.png
```

`正文.md` 中可以这样引用：

```markdown
# 产品更新

![封面](./封面.png)

![桌面预览](<images/桌面 预览.webp>)

![同一张桌面预览](images/桌面%20预览.webp)

![旧版结果](对比/旧版/result.png)
![新版结果](对比/新版/result.png)

![处理流程][flow]

[flow]: images/流程.jpg "处理流程"
```

不同目录中的同名图片会按完整路径分别关联；多次引用同一个文件只导入一份图片素材。

导入素材若与项目内已有图片重名，会自动在素材显示名中加序号，避免影响其他章节使用文件名引用的图片；包内图片仍通过各自的 `asset://...` 正确关联。

Markdown 位于子目录时，仍从它所在的位置计算路径。例如把唯一的文稿放在 `产品更新/稿件/正文.md`，引用同一包中的 `产品更新/images/流程.jpg` 应写成：

```markdown
![处理流程](../images/流程.jpg)
```

`../` 可以返回包内的上级目录，但不能跳出顶层文件夹。

## 路径与文件约定

- 使用标准 Markdown 的行内图片 `![说明](路径)` 或引用式图片 `![说明][标记]`。
- 图片引用必须有对应定义；如果只是展示 `![...]` 这段语法文字，请转义为 `\![...]`，或放入代码块／行内代码。
- 路径使用 `/` 分隔目录，不使用反斜杠 `\`；文件名大小写必须一致。例如 `Cover.png` 不能引用实际的 `cover.png`。
- 支持中文文件名与百分号编码。路径包含空格时，用 `<...>` 包住路径，或把空格写成 `%20`。真实文件名中的 `%`、`?`、`#` 分别写成 `%25`、`%3F`、`%23`，不支持附加 URL 查询参数或片段。
- 文件名和路径按 Unicode NFC 规范化比较；规范化后产生同名冲突的包需要先改名。
- 图片必须实际包含在包内。外网 URL、绝对路径、`data:`、已有 `asset://` 引用，以及原始 HTML `<img>` 不属于此导入格式；请改为包内图片的相对路径。
- 代码块与普通正文保持原样；它们不是需要寻找和导入的图片引用。普通网页链接也不作为图片素材导入。
- 未引用的文件不会上传为图片素材，但仍计入压缩包容量与文件数量；未引用的第二份 Markdown 也会使导入失败。
- 系统忽略常见压缩附带文件：`__MACOSX/`、`.DS_Store`、`._*` 与 `Thumbs.db`。不要把文稿或图片放进这些位置。
- 只支持未加密的 `.zip`，不支持 RAR、7z、符号链接或跨出顶层文件夹的路径。

## 压缩与导入

1. 整理上述文件夹，确认整个目录树只有一份 Markdown，并用本地 Markdown 预览检查图片路径。
2. 在文件夹的**父目录**中选中整个文件夹并压缩：macOS 访达选择“压缩”，Windows 文件资源管理器选择“压缩为 ZIP 文件”。不要只选中文稿与图片文件进行压缩。
3. 打开 OpenTutor 的目标项目，在章节目录中选择要导入的章节。
4. 点击章节编辑区的“导入 ZIP”（窄屏显示压缩包图标）选择文件，也可以将 ZIP 拖入正文编辑区。检查摘要中的目标章节、文稿路径和图片数量，再确认“导入到此章节”。取消时保留当前草稿。
5. 导入成功后，在右侧 Markdown 预览确认正文与图片，再点击“生成视频”。

也可以在父目录使用命令压缩：

```sh
zip -r 产品更新.zip 产品更新
```

确认导入只替换目标章节的 Markdown，并加入实际引用的图片素材；保留章节标题、ID、生成参数和顺序，以及其他章节和历史视频。导入会将图片引用转换为项目内稳定的 `asset://...` 引用，后续生成可以读取这些图片。若一条引用定义同时供图片与普通链接使用，只转换图片用法，普通链接与定义保持原样。

如果目标章节已有视频，修改文稿后它会成为旧版预览，仍可选择、播放和下载；重新生成后才应用新文稿。压缩包导入本身不会开始 AI 生成、配音或 MP4 渲染。

## 容量限制

| 项目 | 上限 |
| --- | --- |
| ZIP 文件大小 | 25 MiB |
| 解压后所有文件总大小 | 150 MiB |
| 压缩包条目数，含文件与目录 | 1,000 |
| 单张引用图片大小 | 15 MiB |
| 单张引用图片像素数 | 4,000 万像素 |
| 包内不同的引用图片数 | 50 |
| 导入后项目图片素材总数 | 50 |
| 导入后整个项目 Markdown 总长度 | 300,000 字符 |

损坏的引用图片、加密或损坏的 ZIP，以及超出限制的包会报告错误，不会用缺图文稿替换当前章节。空 Markdown 可以导入，生成视频前需要补充正文。

## 常见问题

| 提示或现象 | 处理方法 |
| --- | --- |
| 缺少唯一顶层文件夹 | 返回父目录，选中完整文件夹重新压缩；ZIP 顶层不要同时放几个文件夹或零散文件。 |
| 找到多份 Markdown | 检查子目录中的 README、备份和隐藏文件；包内只能保留这次要导入的一份 `.md` 或 `.markdown`。 |
| 找不到引用的图片 | 从 Markdown 所在目录检查路径、大小写和扩展名，确认图片已经放进包中。不要从 ZIP 名称或顶层文件夹名称开始写路径。 |
| 图片路径超出文件夹 | 将图片移入同一顶层文件夹，重新计算相对路径。 |
| 图片类型不支持或无法读取 | 重新导出为静态 PNG、JPEG 或 WebP，再修改引用。不能仅通过改扩展名转换图片。 |
| 超出容量或素材数量 | 缩小图片尺寸、压缩图片、删去包内无关文件，或减少引用图片。已有项目素材也占用总额度。 |
| 导入期间章节内容已变化 | 保留当前稿件，核对目标章节的最新内容后重新发起导入。 |

此规范适用于**导入一个章节的 Markdown 压缩包**。工作台的“导入整份 Markdown”是另一种按标题拆分文稿的操作。
